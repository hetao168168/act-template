# 第七节：让 AI 认识你——仓库初始化三步走

## 开场

前几节，你已经了解了我的 Obsidian 仓库是怎么设计的，也把自己的仓库搭建起来了。

Action 有了，Card 在写，Time 层也跑起来了。

---

接下来，如果我们打开 Claude Code，可以来试一下："帮我整理一下笔记"——AI 会做什么？

它会扫描文件夹，随机提几条建议，然后给你一个看起来有道理但跟你毫无关系的回答。

因为**它不认识你**。

它不知道你的 11 号文件夹放的是什么，不知道你的卡片和目标之间是什么关系，也不知道你现在最想解决的问题是什么。

这一节，就做一件事：**让 AI 第一次认识你的仓库。**

完成这一节之后，你和 AI 的每一次对话都会比之前更有效率，他会更加懂你。

---

## 什么是 Claude Code

很多人用过 Claude，就是那个网页版的聊天界面。你打开浏览器，输入问题，它给你回答——和 ChatGPT、Deepseek 是一样的使用方式。

但 Claude Code 不一样。

**Claude 是一个对话窗口，Claude Code 是一个可以进入你电脑的工具。**

普通的 Claude，它只能看到你粘贴给它的内容。你想让它帮你整理笔记，你得先把笔记复制过去，它处理完了你再手动贴回来。它和你的电脑之间有一堵墙。

Claude Code 是在你的电脑本地运行的。它可以直接读取你硬盘上的文件、新建文件、修改内容、搜索整个文件夹——你不需要复制粘贴，它直接进来工作。

对我们用 Obsidian 的人来说，这个区别非常关键：

> Claude Code 可以直接读取你仓库里的每一篇笔记，理解整个结构，然后帮你写卡片、整理日志、执行工作流。这些事情，网页版的 Claude 做不到。

打一个比方：普通 Claude 是你可以打电话咨询的顾问，每次都要你念文件给它听；
Claude Code 是你的助理，可以直接进你办公室、翻你文件柜、帮你整理桌面的助手。

### 本质：在你的电脑上部署一个 Agent

不管用什么工具，它们做的事情是一样的：**在你的电脑本地运行一个 AI Agent，让它可以替你干活。**

Agent 和普通聊天的区别在于：

- 普通聊天：你问一句，它答一句，每次都是新的开始
- Agent：它可以主动读文件、写文件、执行多个步骤、自己判断下一步做什么——你给它一个目标，它去完成

Claude Code 是 Anthropic 官方出的那个工具，也是我日常用的。但如果你暂时用不了，或者想尝试其他选择，有两个替代方案：

### 替代方案一：OpenCode

OpenCode 是一个开源的 Agent 工具，功能和 Claude Code 类似，但它支持接入多种 AI 模型，不只是 Claude——也可以用 GPT、Gemini、DeepSeek 等。

如果你因为网络或付费原因暂时无法使用 Claude Code，OpenCode 是一个值得尝试的替代。底层换了个模型，但在你电脑本地读写 Obsidian 仓库、执行工作流这件事，逻辑是完全一样的。

### 替代方案二：CC Switch

CC Switch 解决的是一个很现实的问题：**没有订阅 Claude，但仍然想用 Claude Code。**

它的做法是把 Claude Code 的请求转接到其他 AI 服务（比如你已有的 Gemini、GPT-4 的 API 等），让你用 Claude Code 这套工具和操作方式，但背后跑的模型换成你能访问的那个。

对于暂时无法付费订阅 Claude、但想先把这套工作流跑起来的人，CC Switch 是一个过渡方案。

项目地址：[github.com/farion1231/cc-switch](https://github.com/farion1231/cc-switch)

---

**三个工具，本质是同一件事：把 AI 从网页窗口里拉出来，部署到你的本地，让它真正进入你的工作环境。** 这门课以 Claude Code 为主来演示，如果你用的是 OpenCode 或者 CC Switch，操作逻辑是相通的，遇到具体差异的地方自己对照调整即可。

## 我的日常使用方式

目前我常用使用 claude code的方式有三种：

1. 在终端中输入claude，然后让它打开我的新建文件夹进行操作
2. 在obsidian里面内置一个终端插件进行操作
3. 在IDE编程工具上面进行操作

前提是你都需要在本地端部署好claudeCode。
上面三种方式的使用，我以前已经发布了一期文章，你可以进行查看。

**我具体来说一下，我的选择是什么样的？**

一般来说，简单的问题我都会在obsidian这款软件里面处理。
但我有时候会发现这些插件没办法很好支持长对话内容，偶尔会出现页面无法加载、卡顿的问题。

因此对于一些长的问题，我更喜欢在cursor或者Antigravity这一类IDE中去进行操作，因为它是可视化界面，操作体验会更好一些。
如果你购买了 IDE 软件的相关服务，使用cursor、trae、Antigravity会更加合适；

## 第 1 步：把这套 ACT 系统告诉 AI

我们来看一下如何让AI更好的结合你的Obsidian数据库。

要做的动作有两个：

1. 使用claude code，打开你的obsidian文件夹，也就是我这套内容的模板，打开它
2. 把我的这套课程内容的逐字稿放在你的obsidian文件夹里面

你可以对 Claude Code 说：

> "我正在使用一套叫 ACT 的笔记系统。请阅读课程文件夹里的逐字稿，了解这套系统的设计逻辑，然后告诉我你的理解。"


AI 读完之后，对你的 ACT 系统就有了基础认知——它知道三层是什么，知道卡片怎么分类，知道 Time 层怎么运作。

## 第 2 步：请 AI 为每个文件夹写 README

你现在有了 10-Action、20-Card、30-Time 这些文件夹。
但下一次打开新的 Claude Code 会话时，AI 又是全新的——它不记得上次的对话。

解决方法：**让每个文件夹有自己的 README。**

README 就是文件夹的自我介绍，AI 进入文件夹时会自动读取它，立刻知道这个文件夹的用途、结构和注意事项。

你可以这样让 AI 来做这件事：

> "请浏览我仓库里的所有主要文件夹，根据里面的内容和结构，为每个文件夹写一个 README.md 文件。README 需要说明：这个文件夹放什么、子文件夹各是什么用途、使用时有什么注意事项。"

AI 会扫描你的仓库，根据实际内容来写，不是模板套用。

写完之后，你看一遍，如果有和实际不符合的地方，手动修改一下就好。

**为什么这一步很关键？**

有了 README 之后，你每次开始新会话，都可以用一句话让 AI 快速建立上下文：

> "请先读取每个主文件夹的 README"

这比每次重新解释一遍要高效得多。

另外，README 里还可以写下当前项目的行动步骤和进展状态，有利于 AI 在下次对话时快速接上。

## 第 3 步：安装几个实用 Skills

接下来先介绍一个概念：**Skills**。

Skill 是你教给 AI 的一个可复用工作流。

这是官方的文档，你可以看一下：[Claude Code Skills 官方文档](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview)

它是一个存在仓库里的文件，里面写着：这个工作流的目标是什么、需要做哪些步骤、输出什么结果。
你每次需要用这个工作流，直接告诉 AI "用某某 Skill"，它就知道怎么做了——不需要每次重新解释。

而且创建这个skill的难度非常低，你只需要在你的本地系统文件夹下面，下载一个叫做claude creator 的skills就可以了，它会告诉你应该如何使用，帮助你创建对应的skills。

具体的介绍，你可以看下这一期视频！

我这套仓库里已经预置了几个常用的 Skill，下面我带你试用一下。

---

### Skill 1：每日开场

**用途**：每天早上，AI 读取你的周计划和日志，帮你确认今日重点。

使用方式：打开 Claude Code，输入 `/每日开场`，AI 就会执行这个工作流。

它会做什么：

1. 读取本周的周计划，看这周的核心目标是什么
2. 读取昨天的日志，了解昨天完成了什么、遗留了什么
3. 综合两份内容，给你提炼出今天最重要的 1-2 件事

你不需要手动翻文件、手动做判断——AI 帮你做完了，你确认一下就好。

---

### Skill 2：每日收场

**用途**：每天晚上，AI 帮你提取今日洞察，写进日志。

使用方式：打开 Claude Code，输入 `/每日收场`。

它会做什么：

1. 读取今天的日志
2. 提取有价值的想法和洞察
3. 整理成一段总结，写回日志的"今日收获"部分

五分钟，一天的积累不会流失。

---

### Skill 3：收件箱归档

**用途**：当收件箱（日志里的未处理内容）积压时，AI 帮你批量处理。

使用方式：输入 `/收件箱归档`。

它会做什么：

1. 扫描收件箱里的所有未处理条目
2. 判断每条内容的类型（任务 / 卡片素材 / 临时记录）
3. 给出归类建议，你确认后它帮你移动到对应文件夹

你只需要审阅，不需要逐条判断。

---

这 3 个 Skill 是日常节奏的基础。安装完之后，你的 AI 工作流就有了固定的入口。
